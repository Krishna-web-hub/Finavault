The book of what goes wrong

Error handling,
illuminated

Every deliberate failure is one class in one hierarchy, carrying its own status, its own vetted wording, and the fields you need to find it. Routes raise & a single layer translates.

I
Debugging an error
Find its code in the register below, then read that class's docstring in src/finvault/errors.py.
II
A user reported one
Ask for the request_id in the message and grep it. That is the whole search.
III
Adding a failure mode
Add a class to errors.py; raise it where you detect it. Nothing in the API layer changes.
I

Whose fault it is decides everything else

The branch an exception sits in determines its status code, its log level, whether a traceback is attached, and whether the caller is told to retry. None of that is decided at the raise site.

4xx · expected

ClientError

The request itself is wrong — bad token, no clearance, unusable input, oversized upload. Retrying it unchanged fails identically.

Warning, no traceback. The message is safe to return verbatim.

403 · expected

PolicyError

The system refused on purpose. Nothing is broken; the refusal is the correct behavior. Fires on data the caller never named.

Warning, no traceback. Usually becomes a blocked result.

503 · incident

DependencyError

An upstream failed — the LLM provider, Postgres, Qdrant. The caller sees generic wording, because str(exc) here carries provider URLs and error bodies.

Error + traceback. Every catch site must fail closed.

500 · incident

InternalError

Our bug: an invariant we control was violated. Anything that is not a FinVaultError is treated as one of these.

Error + traceback. The fix is code, not config.

III

What becomes of an exception

A genuine sequence, so it is numbered. Each step happens in exactly one file.

i

A request gets an id

Middleware stamps one, binds it for the request, and returns it in X-Request-ID. An inbound id is honored only if it is short and free of control characters — it lands in log records, so a newline could forge log lines.

api/error_handlers.py · RequestContextMiddleware
ii

Auth binds the actor

Once a token verifies, the user id and org join the request context, so every later record names who made the request. This is why get_current_user is async — a contextvar set in FastAPI's threadpool would be discarded.

api/auth.py · add_request_context()
iii

Something raises

The code that detects the problem raises the class that names it — operator detail in the message, grep-able values in context. It does not pick a status, write client-facing wording, or catch its own error to re-raise it as something else.

anywhere in src/finvault/
iv

The handler translates it

One of four handlers — for FinVaultError, HTTPException, validation errors, and everything else — logs it at the level its branch warrants and serializes it into the envelope opposite. This is the only place an exception becomes a response.

api/error_handlers.py
v

The request is logged out

Status and duration, under the same request id as everything else the request emitted.

api/error_handlers.py · request_finished
¶

Two endpoints deliberately break step iv. POST /query and POST /query/stream catch everything and return HTTP 200 with blocked: true and a block_reason — because "no answer" is already a first-class outcome there, and a partial execution trace with a stated reason serves the UI better than an error page.

block_reason is the exception's own code, so the string the frontend shows, the string in the logs, and the string in the audit row are the same one.

IV

One envelope, one log line, one id

What the caller receives

Identical for every failure — ours, FastAPI's, or an unhandled bug.

HTTP/1.1 403 Forbidden
X-Request-ID: 412e2f93…

{
  "error": {
    "code": "access_denied",
    "message": "You are not authorized to
                access the compliance review queue.",
    "retryable": false,
    "request_id": "412e2f93…"
  }
}

What you receive

The same event, carrying the detail kept out of the response.

{
  "level": "WARNING",
  "event": "request_failed",
  "request_id": "412e2f93…",
  "actor": "ba0222e5…",
  "org_id": "org-a",
  "path": "/compliance/review-queue",
  "error_code": "access_denied",
  "role": "analyst",
  "required_role": "compliance_officer"
}

The split is the point: message is vetted wording the class owns; the operator detail and everything in context go only to the log. An unhandled exception is answered with an opaque 500, because its message could carry a connection string, a prompt fragment, or decrypted content.

V

What the codebase holds itself to

  • No module defines its own exception class. They all live in errors.py. The modules that used to define them re-export from there, so existing imports and except clauses are untouched.
  • Routes raise; they do not translate. Fourteen hand-written HTTPException calls each used to invent a status and a message. Adding a failure mode now means adding a class and raising it — the API layer stays as it is.
  • Fail closed, always. A dependency failure never degrades into a guess. A failed retrieval is not "nothing found"; an unreachable compliance reviewer is a block, not an approval; an empty model turn is a truncation failure, not "the model had nothing to say".
  • Log level follows the branch, not the call site. log_exception() decides: expected refusals at warning with no traceback, incidents at error with one. A stack trace on every routine 403 only trains readers to skip stack traces.
  • Nothing is caught silently. Every except either re-raises or logs — including the ones that degrade on purpose, like extraction failing while ingestion continues. The single exception is the numeric-column test in tabular.py, where a ValueError is the answer.
  • Errors carry structured context, not formatted strings. context={"role": role, "required_role": required} becomes log fields you can filter by. It must never hold document plaintext, decrypted content, or credentials.
VI

Finding the record

One JSON object per line, one request_id per request, on every record that request emits. Set FINVAULT_LOG_FORMAT=text for a readable console while developing. DEBUG is safe to run — no call site logs document content or secrets.

request_idCorrelates everything. Also in the response header and every error body.
actor · org_idWho made the request, bound the moment auth resolves.
eventThe log message: a stable snake_case name, never an interpolated sentence.
error_codeThe exception's code. Group by this to count failure modes.
error_typeThe class name — the code's finer-grained companion.
status · duration_msOn request_finished, for every request including the successful ones.

Attaching your own fields

logger.info("document_ingested", extra=extra_fields(document_id=doc.id, chunks=42))

Always extra_fields(...), never a bare extra={...}: a field named like a stdlib LogRecord attribute (module, message, args) makes logging raise. On an error path, a log call is the last thing that should throw.

¶

The one propagation trap. Context follows await and asyncio.to_thread, but not a bare threading.Thread — which is exactly what POST /query/stream uses to run the orchestrator. Capture with request_context() on the way in and restore with run_in_request_context() inside the thread, or every log line from a streamed query is orphaned from the request that caused it.

VII

What holds this in place

The value of a taxonomy is entirely in its consistency, so the invariants are tested rather than documented and hoped for.

test_errors.pyCodes are unique; every class is exported; branch and status agree; context never reaches the client body.
test_error_handlers.pyThe HTTP contract end to end — envelope shape, opaque 500s, request-id round trip, a forged inbound id rejected, log level per branch.
test_auth_errors.pyEvery rejection reports one code; the reason is logged and never returned; the actor is bound to the request's records.
test_observability.pyFields land as real record attributes; context unwinds between requests and crosses into a raw thread.
test_uploads.pyA lying Content-Length is caught mid-stream; the temp file is gone on every exit path.
